# Android 호출어·음성 명령 검증

> 2026-10-20 업데이트: 빌드·테스트 실행 금지는 철회되었습니다. APK 빌드, 단위 테스트 35개, Pixel 3 기기 테스트 10개와 Lint가 통과했습니다. 아래의 미실행 기록은 이전 작업 당시의 상태이며, 현재 결과와 검증 범위는 [BUILD_VALIDATION.md](BUILD_VALIDATION.md)를 참고하세요.

## 미검증 상태

에이전트는 Gradle 빌드·테스트·Lint 및 실기기 측정을 실행하지 않았다. 기준 기기는
Pixel 3 / Android 12이다. 구현 완료와 백그라운드 실사용 검증 통과를 구분한다.
기본 서비스가 연속 인식에 제한을 두는 경우 이 구조만으로 해결됐다고 간주하지 않는다.

## Android Studio 검증 순서

1. Gradle Sync 후 debug 설치한다. Sherpa AAR·모델·샘플 다운로드 작업이 없어야 한다.
   설정의 이전 WAV 진단 버튼도 없어야 한다.
2. `VoiceListeningSessionTest`, `KoreanWakePhraseMatcherTest`, `VoiceLifecyclePolicyTest`,
   명령 해석·모델 출력 검증과 Compose UI 테스트를 실행한다. 가짜 시계/드라이버 테스트는
   인식 요청 중첩, 중복 결과, 준비/최종 응답 제한, 취소·중지 뒤 늦은 이벤트를 검증한다.
3. “헤이 아리아 설정 열어”와 “헤이 아리야 홈으로 가”를 한 호흡으로 말한다.
   부분 결과에서 한 번 진동하고, 최종 확인 뒤 한 번만 실행되어야 한다.
4. 호출어만 말하고 다음 세션이 준비된 뒤 “설정 열어”라고 말한다. 호출어를 반복하지 않아도 된다.
   입력창이 열린 뒤 무발화 8초면 호출어 대기로 돌아가야 한다. 수동 시작·완료도 확인한다.
5. 일반 대화, 이름 단독, “히어리야”, 문장 중간의 호출어는 실행하지 않아야 한다.
   앱 결과와 로그에 호출어 없는 일반 대화가 표시되면 안 된다.
6. 조용한 상태에서 반복되는 무응답 종료는 오류 TTS나 앱 진동을 내지 않아야 한다.
   기본 인식 서비스가 내는 자체 안내음은 따로 기록한다.
7. 디버거/테스트 드라이버로 네트워크·서버·사용 중 오류를 주고 1·2·4·8·15초 재시도를 확인한다.
   6번째 연속 실패에는 오류 유지와 자원 해제가 이루어져야 한다. 준비 콜백만 반복해도 횟수가 리셋되면 안 된다.
8. 재시도 중 수동 시작·전체 중지, 준비 중 중지, 결과 대기 중 중지, TTS 중 중지를 확인한다.
   오래된 콜백/예약으로 인식이 다시 시작되거나 명령이 실행되면 안 된다.
9. 권한 회수, 한국어 데이터 없음, 기본 서비스 비활성화, 요청 제한은 자동 반복 없이 종료되어야 한다.
   연결 오류 후 네트워크를 복구했을 때 정책대로 회복되는지도 확인한다.
10. TTS 안내를 자기 호출어로 받아들이지 않아야 한다. 도움말·재질문 뒤 입력 복귀,
    음성 안내 중 수동 시작, 소리 설정 유지, 취소/듣기 중지를 확인한다.
11. 화면 회전·홈 이동·화면 꺼짐·UI 프로세스 종료 후 호출과 상태 동기화를 확인한다.
    재연결/Speaking도 활성 상태로 보이고, 재시도 중에도 전체 중지가 가능해야 한다.
12. Gemma 설치 전후 같은 항목을 반복해 음성 인식과 모델의 동시 사용도 확인한다.

## 실기기 합격 기준

- 화면 켜짐과 꺼짐 각각 호출 20회 중 18회 이상 활성화 및 명령 처리 성공.
- 한 호흡/분리 입력을 모두 포함하고, 일반 대화 100문장에서 명령 오실행 0회.
- 화면 꺼짐 30분 동안 무음·일반 대화·호출을 섞어도 대기 중단·인식기 중첩·비정상 종료 없음.
- 전체 중지/최종 실패 후 마이크 표시와 WakeLock이 사라지고 Gemma 자원이 해제됨.
- 복구 실패는 오류로 표시되며, 실제 감지 중단이 정상 Waiting으로 계속 표시되지 않음.

APK 식별값, 기본 인식 서비스 이름/버전, 한국어 언어팩, 네트워크 상태, 호출 성공 수,
오탐 수, 인식 종료→다음 준비의 평균/P95 공백, 서비스 안내음 빈도, 시작/종료 배터리·온도와
PSS를 기록한다. 실제 개인 발화 대신 사전에 정한 테스트 문장 번호를 사용한다.

백그라운드 대기가 끊기거나 반복 안내음으로 사용하기 어려우면 전체 완료로 판정하지 않는다.
비행기 모드 결과는 별도로 기록하며 기본 서비스가 오프라인을 지원하지 않는 것을 Gemma 실패로 분류하지 않는다.
