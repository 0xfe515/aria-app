# 음성 명령과 Gemma 통합

## 구현 상태

룰 기반 실행, 앱 내 모델 다운로드/검증, 별도 프로세스 Gemma 추론, 한국어 오프라인 TTS,
백그라운드 결과 알림을 구현했다. 에이전트는 Gradle Sync·빌드·테스트·Lint·기기 측정을
실행하지 않았다. **Pixel 3에서의 구동과 성능을 통과한 것으로 간주하지 않는다.**

완료 판정은 두 단계다.

1. 기본 조작: 아래 명령과 백그라운드/중지/중복 방지의 기기 검증 통과.
2. 전체 완료: 다운로드부터 오프라인 Gemma 추론까지 Pixel 3 / Android 12에서 검증 통과.

## 명령

호출어 뒤 또는 수동 입력 버튼으로 명령을 말한다. 확정된 문장만 실행한다.

| 명령 예시 | 동작 |
| --- | --- |
| 홈으로 가 / 홈 열어 | 홈 탭 이동 |
| 설정 열어 / 설정으로 가줘 | 설정 탭 이동 |
| 안내 소리 켜 / 안내 소리 꺼 / 조용히 해 | 효과음과 TTS 설정 변경, 진동 유지 |
| 현재 상태 알려줘 | 대기·소리·Gemma 상태 안내 |
| 도움말 / 뭐 할 수 있어 | 지원 명령 안내 |
| 취소 / 아니요 | 해석·재질문·보류된 화면 이동 취소 |
| 듣기 중지 / 그만 들어 | 안내 후 마이크·ASR·LLM·WakeLock 해제 |

소리는 Aria 안내 소리만 의미한다. 휴대폰 볼륨이나 다른 앱은 조작하지 않는다.
전체 중지 뒤에는 앱에서 다시 시작한다. 현재 앱의 진단 기능은 수동으로만 실행한다.

화면 밖에서도 설정 변경과 조회를 실행한다. 화면 이동 요청은 30초간 유지하고
알림을 누르거나 앱으로 돌아왔을 때 적용한다. 취소·전체 중지·기한 만료 후에는 적용하지 않는다.
알림 권한이 꺼져 있으면 화면을 강제로 열지 않고 앱을 직접 열도록 안내한다.

룰에 없는 표현은 설치된 Gemma에 전달한다. 모델이 없거나 준비되지 않았으면 기본 명령으로
다시 말하도록 안내한다. 부정문과 모호한 대상은 재질문한다. “그거 꺼”는 30초 이내의 직전
대상이 안내 소리인 경우에만 룰로 해석한다. 여러 동작은 한 번에 실행하지 않는다.
재질문 TTS 뒤에는 호출어 없이 8초간 답을 받는다. 시간이 지나면 미확정 답을 실행하지 않는다.
소리/TTS가 꺼져 있거나 준비되지 않았으면 재질문은 표시만 하고 다음 호출어를 기다린다.

## 모델 준비

- 설정의 다운로드 버튼을 사용한다. Wi-Fi가 기본이며 모바일 데이터는 별도 선택이다.
- DownloadManager가 앱 전용 외부 저장소로 받는다. 앱 재실행 시 다운로드 ID로 상태를 복구한다.
- 파일: `gemma-4-E2B-it.litertlm`, 2,588,147,712 bytes.
- 저장소: https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm
- 고정 revision: `6e5c4f1e395deb959c494953478fa5cec4b8008f`
- SHA-256: `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c`
- 배포 메타데이터 출처: 위 revision의 LFS 포인터. 크기와 SHA-256을 모두 확인한 후
  파일 이름을 바꾸고 검증 마커를 기록한다. 중간 파일은 추론에 사용하지 않는다.
- 약 2.59GB와 여유 공간이 필요하다. 모델 파일/다운로드 ID는 백업·기기 이전 대상에서 제외한다.
- 설치 완료 후 음성 대기 중이면 모델을 준비한다. 중지 상태면 다음 대기 시작 때 준비한다.
- 모델 삭제는 진행 중 해석을 무효화하고 언어 프로세스를 해제한다.
- 추론/준비 실패 후 재시도는 음성 대기를 중지하고 다시 시작한다. 자동 재시작 루프는 없다.
- 한국어 오프라인 TTS 음성을 시스템 설정에서 미리 설치한다. 없으면 진동과 화면/알림으로 대체한다.

## 구조와 제한

`AndroidRecognitionDriver → VoiceListeningSession의 호출어/최종 결과 확인 → CommandCoordinator → 룰 → 필요한 경우 LanguageClient → 검증 → 실행`.
부분 결과·상태 콜백·2초 주기 스냅샷은 실행 이벤트가 아니다. 같은 문장을 새로 말하면 다시 실행한다.
부분 결과·오류 뒤 남은 텍스트·전체 종료에서 취소한 결과는 실행하지 않는다.

서비스의 세션 epoch와 명령 generation으로 취소/새 입력/중지 뒤 늦은 결과를 무시한다.
홈/설정 이동은 서비스 요청 ID를 UI가 소비하고 확인하므로 화면 회전으로 재실행하지 않는다.
UI 콜백 Binder가 죽으면 백그라운드로 판정해 결과를 알림으로 전달한다.
안내 소리 설정의 저장과 변경은 `:wakeword` 서비스 한 곳이 소유한다. 인식 상태는 Waiting/Reconnecting/Speaking으로 구분한다.

LiteRT-LM 0.16.1, CPU 두 스레드, 최대 컨텍스트 2048토큰, 응답 96토큰,
thinking/MTP/자동 도구 실행 비활성, 텍스트 입력만 사용한다.
비전·오디오 인코더를 로드하지 않는다. 호출어와 명령 모두 Android 기본 음성 인식 서비스가 담당한다.
한국어 언어팩·오프라인/네트워크 정책은 기기 기본 서비스를 따른다. 정식 호출어가 문장 시작에 있을 때만 활성화한다.
한 호흡 입력과 호출어만 말한 뒤 이어 말하기를 지원한다. [OFFLINE_WAKEWORD.md](OFFLINE_WAKEWORD.md)를 참고한다.
공식 API: https://developers.google.com/edge/litert-lm/android

`:language`의 네이티브 초기화/추론은 직렬 실행한다. 준비 60초/해석 15초에 사용자 대기를
끝내고 실행을 포기한다. 네이티브 호출이 아직 반환하지 않았다면 추가 추론을 겹치지 않는다.
전체 중지/삭제는 전용 언어 프로세스를 종료해 멈춘 네이티브 호출의 자원도 회수한다.
음성 디코딩 스레드에서 LLM이나 파일 해시 계산을 하지 않는다.

모델은 명령 하나만 담은 JSON을 반환한다. 알려진 enum 외 명령·추가 인자·복수 결과는
실행하지 않는다. 결과 TTS는 코드의 고정 문구이며 모델 자유 응답을 읽지 않는다.
발화·컨텍스트·모델 출력은 메모리에만 보관하며 로그/파일에 기록하지 않는다.
설정에는 마지막 준비/해석 시간을 표시한다. 메모리·배터리·온도는 기기 프로파일러로 측정한다.
TTS 동안 Android 인식기를 취소·해제한다. 완료/오류 후 기존 500ms 대기와 300ms 재시작 정책으로 복귀한다.
음성으로 TTS를 끼어들어 중단하는 기능은 제공하지 않으며 화면/알림의 중지 버튼은 동작한다.
듣기 중지 명령은 안내 완료 또는 최대 5초 뒤 정리하므로 TTS 완료 콜백이 없어도 중지한다.

## Android Studio 검증 순서

1. Gradle Sync, debug 빌드 후 Pixel 3 / Android 12에 설치한다. 모델 다운로드 전 기본 명령을 먼저 확인한다.
2. `RuleCommandInterpreterTest`, `ModelCommandParserTest`, `VoiceListeningSessionTest`, `KoreanWakePhraseMatcherTest`, 기존 생명주기 테스트, Compose UI 테스트,
   `ModelCommandValidationTest`를 실행한다. 에이전트는 테스트 코드를 작성했으나 실행하지 않았다.
3. 설정에서 Wi-Fi 다운로드, 취소/재시도, 앱 종료 후 복귀, 저장 공간 부족, 네트워크 단절을 확인한다.
   디버거로 내려받은 중간 파일을 손상시켜 설치 완료로 표시되지 않는지 확인한다.
4. Gemma 설치 뒤 준비 시간과 메모리를 기록한다. 비행기 모드에서 “소리가 좀 거슬려” 같은
   변형 문장 20개를 입력한다. 받아쓰기 오프라인 지원 여부는 기본 인식 서비스와 언어팩에 따라 별도로 확인한다. 18개 이상 의도 일치, 해석 15초 이내를 전체 완료 기준으로 한다.
5. “설정 열지 마”, “그거 꺼”(대상 없음), 두 동작 요청, 미지원 명령은 오실행하지 않아야 한다.
   소리 켜기 뒤 “그거 꺼”는 동작하고 30초 후에는 되물어야 한다.
6. 부분 결과/최종 결과/수동 완료가 겹쳐도 한 번만 실행되는지, 같은 말을 다시 하면 새로 실행되는지 확인한다.
   해석 중 새 호출/취소/전체 중지 뒤 이전 모델 결과가 실행되지 않아야 한다.
7. 화면 꺼짐·홈 버튼 이동·UI 프로세스만 종료한 상태에서 소리 설정 변경과 상태 조회를 확인한다.
   화면 이동은 알림으로 완료하며 회전/재진입/주기적 조회로 반복 이동하지 않아야 한다.
8. TTS 안내 중 자기 안내를 명령으로 받아들이지 않는지 확인한다. 재질문은 안내가 끝난 후 답하고,
   무응답 8초 후 복귀, TTS 데이터 없음/실패, 안내 소리 끄기와 재실행 후 설정 유지도 확인한다.
9. 언어 프로세스 강제 종료와 준비/추론 지연을 주어 기본 명령이 유지되는지 확인한다.
   전체 중지 후 마이크 표시·WakeLock·언어 프로세스 자원이 해제되어야 한다.
10. ASR+Gemma 동시 실행, 화면 꺼짐 30분 동안 비정상 종료 없음, 온도/배터리/PSS를 기록한다.
    한 호흡 입력과 호출어만 말한 뒤 명령을 말하는 흐름을 모두 확인한다. 세션 사이 감지 공백은 별도로 측정한다.

기기 검증 기록에는 APK 식별값, 기기/OS, 모델 revision, TTS 엔진/오프라인 음성 설치 여부,
명령별 정답·지연, 초기화 시간, PSS와 30분 대기 결과를 남긴다. 실제 사용자 발화 대신
사전에 정한 테스트 문장 번호를 사용한다.
