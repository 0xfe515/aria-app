# Feedback runtime settings (2026-11-10)

`FeedbackSettingsClient` talks to the non-exported `.settings.FeedbackSettingsProvider` through `ContentResolver.call`. Android hosts this provider in the app's default main process; it serializes updates and commits a single settings tuple before publishing a change notification. This makes the main UI and `:wakeword` VoiceService use the same durable state without relying on multiprocess SharedPreferences observers. Clients expose a cached `StateFlow` and unregister their `ContentObserver` on close.

Defaults are app volume 100%, `NORMAL` frequency, and caution enabled. NORMAL retains 2.5 s warning / 6 s caution cooldowns and 1.2 s urgent / 2.5 s distance vibration cooldowns. FREQUENT scales repeat cooldowns to half (with bounded minima); QUIET doubles them. Policy state is not reset on configuration changes, while escalation and changed-target gates remain immediate. Disabling caution filters CAUTION at the hazard policy and distance vibrator; queued transient caution toast work rechecks the setting before delivery. VoiceService also performs a readback before handling queued CAUTION Binder events; the command coordinator keeps a cached caution gate as a final speech-path check. WARNING and URGENT remain active. Walking diagnostics record caution suppression as `USER_CAUTION_DISABLED`, preserving the explicit user-selected reason separately from camera, model, and detection failures.

Android TTS receives `KEY_PARAM_VOLUME` for each utterance and `SoundPool` cues use the same 0..1 app gain. No system volume is changed. General settings uses the same client for volume, frequency, and caution controls. Voice commands use the public `FeedbackSettingsClient` methods through the command worker. Hazard severity also crosses the VoiceService Binder boundary via `postHazardAlertWithSeverity`; the legacy AIDL entry point remains WARNING-compatible, and caution events are filtered again in the voice process before speech effects.
