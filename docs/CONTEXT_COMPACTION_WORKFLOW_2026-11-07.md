# 다음 작업부터 적용할 컨텍스트 운영

사용자 요청에 따라 [You don’t need long context, arXiv:2611.05306v1](https://arxiv.org/html/2611.05306v1)의 실행 상태 중심 압축과 필요한 자료만 조회하는 원칙을 다음 작업부터 적용한다. Appendix A는 과거 실행의 줄거리보다 원래 과제, 현재 의도와 다음 단계, 완료 조건과 관련 산출물을 보존하는 요약을 권한다.

## 적용 절차

1. 작업 시작 시 원래 요청과 최신 사용자 수정, 완료 조건, 금지 사항을 짧은 작업 명세에 보존한다. 기존 Orca 9개 필드 계약은 유지한다.
2. 파일·로그는 저장소와 외부 로그 경로에 두고 필요한 심볼과 범위만 조회한다. 실제 오류, 종료 코드, 근거 위치가 잘리지 않도록 한다.
3. 의미 있는 단계 완료, 인계 및 기존 15분 체크포인트에서 `.orca/drops/continuation/<TASK_ID>.md`를 갱신한다. 전체 대화나 반복 로그 대신 아래 실행 상태를 남긴다.
4. 지원되는 압축 또는 새 세션으로 이어갈 때 원래 요청과 이 실행 상태를 사용한다. 실제 diff·산출물·현재 Orca 상태를 재확인한다. 실행 중 작업자의 소유권을 해제하거나 중복 작업자를 만들지 않는다.

## 보존할 실행 상태

- 원래 과제, 최신 사용자 수정·우선순위, 완료 조건.
- 현재 작업과 의도, 남은 단계와 바로 실행할 다음 행동.
- Run/Task/Dispatch, 작업 경로, 독점 소유 파일, 다른 작업자와 의존성.
- 변경 파일과 관련 산출물 위치·필요한 해시, 결정과 이유.
- 완료·실패·미실행 검증을 구분한 명령, 실제 종료 코드, 원본 로그 경로.
- 미해결 질문, 실패한 접근과 반복하지 말아야 할 조건.

## 적용 한계와 평가

현재 런타임에 노출되지 않은 강제 컨텍스트 리셋이나 정확한 토큰 임계값을 설정했다고 주장하지 않는다. 매 도구 호출마다 세션을 버리는 SAC 실험 방식을 그대로 강제하지 않는다. 자동화·전역 설정·계정·기존 검증 요구는 변경하지 않는다.

논문의 좁은 컨텍스트 결과는 평가 모델·과제·하네스에 한정된다. 가장 좁은 설정에서 정확도가 낮아진 사례도 있다. 포화 H100 처리량 비교와 추정 최적화 비용을 현재 API 청구 절감률로 옮기지 않는다. 새 입력·캐시 입력·출력 토큰의 변화도 서로 다르므로 보편적인 절약을 보장하지 않는다.

실제 사용량을 제공하는 환경에서만 비교 가능한 완료 과제의 총 사용량, 재시도, 검증 결과를 기록한다. 사용량이 없으면 미측정으로 표시한다. 요약으로 생긴 누락·재조회·재작업도 기록하며 품질과 검증을 우선한다.
